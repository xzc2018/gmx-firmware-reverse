# vlsim: модель платы GMX для Verilator

Модель платы GMX целиком: процессор Z80, ПЛИС EPF8452A, CPLD EPM7064S, Flash 28F400, два модуля SIMM, логика платы. На вход подаётся образ Flash, на выходе - кадры видеовыхода в PNG и журналы шины. Результаты прогонов: [../docs/SIMULATION.md](../docs/SIMULATION.md).

## Состав

| каталог, файл | содержимое |
|---|---|
| `rtl/gmx_board.v` | плата по принципиальной схеме: связи микросхем, шины D, DB, MD, SD, буферы DD4, DD8, DD11, DD12, защёлки DD5, DD9, диодные И (CSROM, RESET), со стороны основной платы клавиатура (порт `#FE`) и NMI от кнопки Magic |
| `rtl/tv80z.v` | интерфейс шины Z80 вокруг ядра tv80 |
| `rtl/vl_prims.v` | триггеры моделей ПЛИС и CPLD |
| `third_party/tv80/` | ядро Z80 tv80 (лицензия LGPL, файл `LICENSE`) |
| `models/orig/` | модели ПЛИС (схемы Scorpion и PentaGON) и CPLD, полученные из исходных прошивок: битстримов образа `gmx12501.rom` и конфигурации CPLD; битстримы `scorpion.rbf`, `pentagon.rbf` |
| `models/rebuilt/` | то же для прошивок, собранных из исходных текстов этого репозитория (`gmx.rom`, `gmx_cpld.pof`) |
| `sim_main.cpp` | тактирование 14 МГц, загрузка ПЛИС, Flash, видео, клавиатура, сценарий, журналы, сохранение состояния |
| `testbench/*.txt` | сценарии тестбенча |
| `build.cmd` | сборка (Verilator, MSVC) |
| `run.js`, `compare.js` | запуск, тестбенч, сравнение прогонов (Node.js) |

Модель ПЛИС содержит по одной таблице LUT и одному триггеру на каждую логическую ячейку, связи соответствуют трассировке битстрима. Модель CPLD содержит сумму произведений, триггер, такт, сброс, установку и управление выходом каждой макроячейки.

## Тестбенчи

| тестбенч | модели | образ Flash |
|---|---|---|
| `orig` | `models/orig` | исходный образ; собирается из `roms/` и исходных битстримов командой `node tools/verify.js` |
| `rebuilt` | `models/rebuilt` | `gmx.rom` этого репозитория |

Сценарий тестбенча (`node vlsim/run.js tb`):

| этап | действия | время, мс |
|---|---|---|
| `boot` | включение питания с нажатой DELETE (CS + 0), меню GMX Loader; состояние сохраняется на 3700 мс | 0-3702 |
| `pentagon` | клавиша 4 (схема PentaGON), меню 128, кнопка Magic, TR-DOS | 3700-10600 |
| `komposit` | клавиша 5 (схема Komposit), меню 128 | 3700-8600 |
| `boardtest` | клавиша 6 (тест платы GMX) | 3700-8100 |
| `scorpion` | ENTER (схема Scorpion), теневой монитор, тест ОЗУ 2 МБ, меню 128 | 3700-30100 |

Для каждого этапа оба тестбенча сравниваются: кадры (побайтно), последовательность событий шины (`io.log`), события загрузки ПЛИС.

## Сборка и запуск

Требуется:
- Verilator 5.x, путь к установке в переменной `VERILATOR_ROOT`;
- Microsoft Visual C++ (определяется автоматически, либо переменная `VCVARS` с путём к `vcvars64.bat`);
- Node.js.

```
vlsim\build.cmd orig
vlsim\build.cmd rebuilt
node vlsim/run.js tb                                   оба тестбенча и сравнение, результаты в vlsim\out\
node vlsim/run.js sim orig vlsim\testbench\boot.txt --ms 4000 [--save 3700 menu.sav]
node vlsim/run.js sim orig my.txt --ms 9000 --load vlsim\out\orig\menu.sav
node vlsim/run.js compare vlsim\out\orig\pentagon vlsim\out\rebuilt\pentagon
```

Сборки, результаты прогонов, сохранённые состояния и образ `out\orig.rom` находятся в `vlsim\out\`; `clean.bat` в корне удаляет этот каталог.

Строки сценария имеют вид `<мс> <команда> [аргумент] [удержание_мс]`:

| команда | действие |
|---|---|
| `key <K>` | клавиша: `0`-`9`, `A`-`Z`, `ENTER`, `SPACE`, `CS`, `SS` |
| `keys <TEXT>` | последовательный набор |
| `magic`, `reset`, `turbo` | кнопки |
| `shot <файл.png>` | сохранить следующий полный кадр |
| `end` | остановить |

Ключи `gmxsim.exe`:

| ключ | действие |
|---|---|
| `--save <мс> <файл>`, `--load <файл>` | сохранить или загрузить состояние |
| `--jumps <от> <до>` | журнал переходов |
| `--bus <от> <до>` | журнал циклов шины |
| `--watch <от> <до>` | журнал обращений к адресам (шестнадцатеричные) |
| `--crop <отсчёты>` | обрезка кадра слева |
| `--dram 512\|1024`, `--tref <мс>`, `--decay` | контроль регенерации DRAM: число строк микросхем (1024 - 1M x 4, модули из 3 микросхем; 512 - 1M x 1), период регенерации (по умолчанию 16 / 8 мс), порча данных просроченной строки; итог в `sim.log`: наибольший интервал между регенерациями строки с записанными данными, число просроченных строк, циклов CBR и циклов CBR при WE/ = 0 |
| `--scorpion-alt <файл.rbf>` | второй битстрим, по которому загружается модель схемы Scorpion (образ с блоками двух компиляций одной схемы, например `gmx_keepboot.rom`) |

Скорость - около 15-20 мс работы платы за секунду. Сохранённое состояние совместимо только с той моделью, которой оно создано.

## Допущения модели

Модель работает без задержек. Места, где схема опирается на соотношение задержек, моделируются так:
- **CPLD.** Входы данных (адрес, данные, IORQ/, MREQ/, RD/, M1/) поступают на полпериода 14 МГц позже глобального такта WR/.
- **ПЛИС.** Регистр с тактом, отличным от 14 МГц, принимает значение D, установившееся до текущего фронта 14 МГц.
- **Шина D.** После снятия всех источников значение держится 4 полупериода 14 МГц, затем подтяжка RN2 даёт `FF`. Шины MD, SD, DB сохраняют последнее значение.
- **Z80:**
  - выборка команды: MREQ/RD с T1 (спад) до T3 (фронт), регенерация MREQ с T3 (спад) до T4 (спад);
  - чтение памяти: MREQ/RD с T1 (спад) до T3 (спад), данные по T3 (спад);
  - запись памяти: MREQ с T1 (спад) до T3 (спад), WR с T2 (спад) до T3 (спад), данные с T1 (спад);
  - ввод-вывод: IORQ, RD/WR с T2 (фронт) до T3 (спад);
  - WAIT по спаду T2;
  - вектор IM 2 читается с шины в цикле подтверждения прерывания.
- **Загрузка ПЛИС.** Длится 2 мс. Блок схемы выбирается по адресу, который выдаёт CPLD (CS1, CS27, A13, RA16-RA18), и сравнивается с битстримами `models/<вариант>/*.rbf`. Пока ПЛИС не загружена, её выводы отключены, CONF_DONE = 0 удерживает RESET.
- **Flash.** Образ хранится в логическом порядке страниц; бит 15 физического адреса = CS1, бит 14 = CS27.
- **DRAM.** 2 x 1 М x 8; строка по RAS (спад), столбец по CAS (спад), запись по CAS или WE (спад).
- **Регенерация DRAM.** Спад RAS при CAS/ = 1 обновляет строку MA в обоих модулях (RAS общий), спад RAS при CAS/ = 0 - цикл CAS-before-RAS модуля, строка по внутреннему счётчику. Для микросхем на 512 строк бит MA9 при регенерации не учитывается. Каждую 1 мс проверяются строки, в которые выполнялась запись.
- **Цвета PNG.** Палитра ZX Spectrum: вывод ПЛИС G (1) - синий, R (3) - красный, B (84) - зелёный.
