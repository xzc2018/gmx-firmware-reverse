# Формат конфигурации Altera FLEX 8000 (EPF8452A)

Документ описывает формат конфигурационных данных ПЛИС Altera EPF8452A (семейство FLEX 8000, корпус PLCC84) и их размещение во Flash-ПЗУ Scorpion GMX. Кодирование получено из файлов базы устройств MAX+PLUS II 10.23 и поведения компилятора.

Описание схем GMX: [GMX_FPGA_scorpion.md](GMX_FPGA_scorpion.md), [GMX_FPGA_pentagon.md](GMX_FPGA_pentagon.md). Исходные тексты схем: [../fpga/scorpion/](../fpga/scorpion/), [../fpga/pentagon/](../fpga/pentagon/). Формирование адреса при загрузке ПЛИС: [CPLD_EPM7064S.md](CPLD_EPM7064S.md).

---

## 1. Кристалл EPF8452A

| ресурс | количество |
|---|---|
| логические ячейки (LE, MCELL) | 336 = 42 LAB x 8 |
| LAB (блоки ячеек) | 42 = 2 ряда (A, B) x 21 столбец |
| входные линии LAB (PIA) | 24 на LAB, всего 1008 |
| трассы строк FastTrack (GH) | 168 на ряд, всего 336 |
| трассы столбцов FastTrack (GV) | 16 на столбец, всего 336 |
| I/O на концах строк (HIO) | 16 на ряд, всего 32 |
| I/O на концах столбцов (VIO) | 4 на столбец, всего 84 |
| выделенные входы (FINP) | 4 |
| глобальные такт / сброс / OE | PCLK x2, PCLR x2, POE x2 |
| конфигурационные биты | 59572 = 212 кадров x 281 бит |

Корпус PLCC84. Распиновка платы GMX с именами цепей: [fpga_pins.csv](fpga_pins.csv).

## 2. Контейнер во Flash-ПЗУ GMX

Схема ПЛИС хранится в 8-КБ блоке Flash-ПЗУ (банк 0, адреса 0x2000...0xDFFF).

| смещение в блоке | размер | содержимое |
|---|---|---|
| 0x0000 | 0x1FE6 | битстрим (раздел 3); после данных до 0x1FE5 включительно - заполнение `FF` |
| 0x1FE6 | 8 | дата, ASCII (`17.02.99`) |
| 0x1FEE | 1 | значение для порта `xx00`, старший полубайт (FIXROM / BLKEXT / BLKEX2 / ST/PENT); `FF` - значение по умолчанию |
| 0x1FEF | 1 | значение для порта `#7EFD`, старший полубайт: биты 4-6 - банк ПЗУ; `FF` -> 0x40 (банк 4) |
| 0x1FF0 | 10 | имя схемы, ASCII |
| 0x1FFA | 2 | CRC-16/CCITT (полином 0x1021, начальное значение 0xFFFF) по байтам 0x0000-0x1FF9, little-endian |
| 0x1FFC | 4 | 0 |

**Номер схемы -> блок.** Адрес блока (в порядке страниц образа Flash) по номеру схемы CONF = 0..7 из порта `xx00`:

| CONF | адрес блока |
|---|---|
| 0, 1, 3 | 0x2000 |
| 2 | 0xC000 |
| 4 | 0x8000 |
| 5 | 0xA000 |
| 6 | 0x4000 |
| 7 | 0x6000 |

ПЛИС загружается из Flash в активном параллельном режиме. Запись `CONF | 8` в порт `xx00` устанавливает nCONFIG = 0; на время загрузки CPLD формирует адресные биты 13..15 блока ([CPLD_EPM7064S.md](CPLD_EPM7064S.md), раздел 2.8).

## 3. Битстрим

Формат битстрима совпадает с файлами `.ttf` / `.rbf` MAX+PLUS II.

```
байты 0x00..0x06   FF FF 6F 34 43 FA FF         заголовок
байт  0x07         F6                           опции (раздел 3.2)
байт  0x08         FF                           опции (раздел 3.2)
байты 0x09..0x2B   FF                           преамбула
с байта 0x2C       212 кадров по 296 бит; биты в байте идут младшим первым (LSB-first)
после кадров       FF
```

Кадр (296 бит, нумерация с 0):

| биты | назначение |
|---|---|
| 0 | `0` - старт |
| 1...281 | 281 бит конфигурации |
| 282...289 | CRC-8 по битам 1...281 (раздел 3.1) |
| 290...295 | `111111` - стоп |

### 3.1 CRC-8 кадра

Полином x^8+x^4+1 (0x11), начальное значение 0xFF. Данные - биты 1...281 кадра в порядке номеров, первый бит старший (MSB-first). Результат записывается в биты 282...289, начиная со старшего.

```python
def crc8(bits, c=0xFF):            # bits = кадр[1:282]
    for b in bits:
        fb = ((c >> 7) & 1) ^ b
        c = (c << 1) & 0xFF
        if fb: c ^= 0x11
    return c
```

### 3.2 Заголовок: опции устройства

Опции устройства изменяют только байты 7 и 8 заголовка; конфигурационные биты от них не зависят. Все опции активны нулем. Значение без опций: байт 7 = `F6`, байт 8 = `FF`.

| опция (`.acf`) | байт | бит | значение при включении |
|---|---|---|---|
| ENABLE_DCLK_OUTPUT | 7 | b7 | F6 -> 76 |
| RELEASE_CLEARS | 7 | b6 | F6 -> B6 |
| AUTO_RESTART | 7 | b5 | F6 -> D6 |
| USER_CLOCK | 7 | b4 | F6 -> E6 |
| DISABLE_TIME_OUT | 8 | b0 | FF -> FE |

При включении всех пяти опций байт 7 = `06`, байт 8 = `FE`. Опции SECURITY_BIT, PASSIVE_SERIAL и JTAG заголовок не изменяют.

В схемах GMX байт 7 = `76`: включена опция Enable DCLK Output in User Mode, остальные опции выключены.

## 4. Адрес бита -> позиция в кадрах

Файлы базы устройства (`.daf`, `.maf`) адресуют конфигурационные биты номером A = 0...59571. Порядок кадров обратный:

```
кадр  F = 211 - A // 281
бит   b = 281 - A %  281          (бит 0 кадра - стартовый)
обратно:  A = (211 - F)*281 + (281 - b)
```

Каждый единичный бит битстрима относится к ресурсу `.daf`, к переключателю `.maf` или к значению по умолчанию (раздел 5.1).

## 5. Описание кристалла в базе MAX+PLUS II

Описание кристалла хранится в трех файлах каталога MAX+PLUS II:

| файл | содержимое |
|---|---|
| `f8452084.daf` | ресурсы и адреса бит для корпуса PLCC84 |
| `f8452.maf` | граф трассировки |
| `f8452084.ddf` | выводы корпуса |

Числа в файлах - 32-битные слова little-endian.

### 5.1 `.daf` - Device Assembler File

**Заголовок.** Смещения в байтах:

| смещение | значение | поле |
|---|---|---|
| 0x00 | `DAF\0` | сигнатура |
| 0x08 | 59572 | total_bits |
| 0x2C | 24 | pt_wls |
| 0x30 | 78 | arch1_bits |
| 0x38 | 84 | n_pins |
| 0x3C | 336 | n_mcs |
| 0x40 | 42 | n_labs |
| 0x44 | 8 | n_data_bits |
| 0x48 | 434 | n_default_groups |
| ... | | lab_clocks = 2, lab_clears = 2, initial_arr_val = 0, first_pia_addr = 59573, bit_shift = 3, bit_mask = 7 |

**Секции ресурсов** (`arch_hdr1`) идут подряд с 0xD0 до 0x2D768:

```
arch_type, arch_value, num_bits, offset, index|FFFFFFFF, 0, rows, cols,
num_select, select[num_select], mode, FFFFFFFF, 0, FFFFFFFF x (cols+3),
rows x [ FFFFFFFF, addr_0 ... addr_{cols-1} ]        (addr = FFFFFFFF - бита нет)
```

- `arch_value` - значение, которое записывается при включении ресурса. У секций 0x06, 0x2D и экземпляров 0x46 № 8-15 arch_value = 0. Для 0x46 значение 0 кодирует выбор GV № i+8 (раздел 6.4). Значения бит секций 0x06 и 0x2D приведены в таблице секций.
- `index` - номер экземпляра для типов, имеющих несколько экземпляров (0x41, 0x42, 0x46, 0x48, 0x49, 0x4A, 0x50, 0xA6).

**Значения по умолчанию.** 434 записи с 0x2D7B4, формат `start_addr, num_bits, step, value`. Массив бит заполняется значением `initial_arr_val` (0), затем для каждой записи выполняется `for k < num_bits: bit[start + k*step] = value`. В EPF8452A все записи описывают одиночные биты: 380 со значением 1 и 54 со значением 0. Из секций ресурсов значения по умолчанию затрагивают только секции IOE 0x34, 0x3C и 0x3F (все 1). Секции 0x06 и 0x2D значений по умолчанию не имеют; у неиспользуемых LE их биты равны 0.

**Таблица секций.** Строка - номер LE (раздел 6.1), LAB, вывод или трасса.

| тип | экз. | строки x бит | назначение |
|---|---|---|---|
| 0x27 | 1 | 336 x 16 | LUT ячейки, бит i = LUT[i] |
| 0x48 | 4 | 336 x 18 | выбор входа LUT № 0...3 (раздел 6.2) |
| 0x06 | 1 | 336 x 1 | триггер: выход LE = Q |
| 0x28 / 0x29 | 1 | 336 x 1 | выбор такт- / сброс-линии LAB: 1 = линия 1, 0 = линия 0 |
| 0x2D | 1 | 336 x 1 | обычный режим (1); 0 у занятой LE - арифметический режим или счетчик |
| 0x2A / 0x2C | 1 | 336 x 1 | режим счетчика (up/down) / счетчик со сбросом |
| 0x2B | 1 | 336 x 1 | режим "сброс + установка / асинхронная загрузка" |
| 0x2E | 1 | 336 x 1 | каскад: выход = LUT AND выход LE k-1 того же LAB |
| 0x41 / 0x42 | 2 | 42 x 4 | такт- / сброс-линия k LAB от выделенного входа (one-hot) |
| 0x49 / 0x4A | 2 | 42 x 18 | такт- / сброс-линия k LAB от линии PIA или обратной связи (код как у 0x48) |
| 0x2F / 0x30 | 1 | 42 x 2 | инверсия такт- / сброс-линии k |
| 0x33-0x3F | 1 | 84 x 1...4 | IOE, строка e = вывод корпуса e+1 (раздел 6.5) |
| 0x50 | 21 | 6 x 2 | периферийная шина e0-e5 (OE / такт / сброс IOE) <- GH |
| 0xA6 | 4 | 6 x 2 | периферийная шина e0-e5 <- выделенный вход |
| 0x43-0x45 | 1 | 2 x 2 | инверсия линий периферийной шины |
| 0x46 | 16 | 21 x 2 | выбор GV -> GH (раздел 6.4) |
| 0x47 | 1 | 172 x 2 | источник GH: 0 - своя LE, 1 - GV |

### 5.2 `.maf` - граф трассировки

Файл описывает элементы трассировки (MCELL, PIA, GH, GV, HIO, VIO, FINPGH) и переключатели между ними. Переключатель задает источник, приемник (`out`) и адрес конфигурационного бита. Номер MCELL в `.maf` совпадает с номером LE в `.daf`.

### 5.3 `.ddf` - выводы корпуса

Таблица соответствия выводов корпуса элементам HIO/VIO `.maf` хранится в `f8452084.ddf` со смещения 0x9160 (раздел 6.5).

## 6. Кодирование ресурсов

### 6.1 Номера ячеек и LAB

```
LCk_A<col>  ->  LE = (col-1)*8 + (k-1)          LAB = col-1        (ряд A = LAB 0...20)
LCk_B<col>  ->  LE = 168 + (col-1)*8 + (k-1)    LAB = 21 + col-1   (ряд B = LAB 21...41)
k = 1...8, col = 1...21
```

### 6.2 Ячейка: LUT и четыре входа

**LUT.** `LUT = SUM( bit(0x27[LE][i]) << i )`. Выход ячейки равен `LUT[in3*8 + in2*4 + in1*2 + in0]`, без инверсии. Примеры: `in3` -> `FF00`, `in3 & in2` -> `F000`, `!in0` -> `5555`.

**Вход LUT № s** (s = 0...3) задается 18 битами `0x48#s[LE]`. Допустимы два состояния: все биты равны 0 (вход не подключен, читается как 1) или установлены ровно два бита (a < b).

| код (a, b) | источник |
|---|---|
| (9+j, 17), j = 0...5 | линия PIA своего LAB № 4j |
| (j, 17), j = 0...5 | линия PIA № 4j+1 |
| (8, 9+j), j = 0...5 | линия PIA № 4j+2 |
| (j, 8), j = 0...5 | линия PIA № 4j+3 |
| (15,17) / (6,17) / (8,15) / (6,8) / (16,17) / (7,17) / (8,16) / (7,8) | обратная связь от LC1 / LC2 / LC3 / LC4 / LC5 / LC6 / LC7 / LC8 своего LAB |

### 6.3 Линия PIA <- источник

У каждой линии PIA ровно один источник (one-hot): установлен бит одного переключателя `.maf` с `out = PIA`. Источник - трасса GH своего ряда (элемент типа 1) или FINPGH (элемент типа 2, выделенный вход). У каждой линии 13-15 возможных источников.

### 6.4 GH (трасса строки) <- источник

У каждой GH есть один общий бит "GH используется" в `.maf`. Этот бит записан у всех ее источников: своей LE, двух GV и, у 32 трасс GH, двух HIO.

Выбранный источник задают секции `.daf`:
- 0x47 (строка = номер GH в ряду, бит = ряд): 0 - своя LE (MCELL, у которой эта GH указана в `out`), 1 - GV.
- 0x46 #i (строка = столбец, бит = ряд): экземпляры i и i+8 имеют общие адреса бит и противоположную полярность. Значение 1 выбирает GV № i столбца, значение 0 - GV № i+8.

### 6.5 GV, выводы, глобальные сигналы

**Связи:**
- GV <- источник: LE подключается к каждой из своих двух GV отдельным битом `.maf`; VIO подключается к GV своим битом.
- HIO/VIO <- источник: one-hot из GH / GV.

**Выводы (IOE):**
- Строка IOE e соответствует выводу корпуса e+1.
- Строки без бит соответствуют выводам, не являющимся I/O: 5, 10, 11, 12, 17, 26, 31, 32, 33, 38, 47, 52, 53, 54, 59, 68, 73, 74, 75, 80.
- HIO 0-15 находятся в ряду A, HIO 16-31 - в ряду B. VIO k находится в столбце k//4+1.

| выводы | элементы `.maf` |
|---|---|
| 1, 2, 3, 4, 6, 7, 8, 9 | VIO 40, 36, 28, 24, 20, 12, 8, 4 |
| 13, 14, 15, 16, 18, 19, 20, 21 | HIO 0, 2, 4, 6, 8, 10, 12, 14 |
| 22, 23, 24, 25, 27, 28, 29, 30 | HIO 16, 18, 20, 22, 24, 26, 28, 30 |
| 34, 35, 36, 37, 39, 40, 41, 42, 43, 44, 45, 46, 48, 49, 50, 51 | VIO 3, 11, 15, 19, 27, 31, 35, 43, 47, 51, 59, 63, 67, 75, 79, 83 |
| 55, 56, 57, 58, 60, 61, 62, 63 | HIO 31, 29, 27, 25, 23, 21, 19, 17 |
| 64, 65, 66, 67, 69, 70, 71, 72 | HIO 15, 13, 11, 9, 7, 5, 3, 1 |
| 76, 77, 78, 79, 81, 82, 83, 84 | VIO 81, 76, 72, 68, 60, 56, 52, 44 |

**Выделенные входы:** FINP0 = вывод 12, FINP1 = вывод 73, FINP2 = вывод 31, FINP3 = вывод 54. FINPGH i соответствует FINP i%4 в ряду i//4. Индекс d выделенного входа одинаков в 0x41/0x42 (бит d) и в 0xA6 (экземпляр № d).

**Биты IOE на вывод:**

| секция | по умолч. | назначение |
|---|---|---|
| 0x34 | 1 | OE включен постоянно; 0 - OE берется из 0x33, при отсутствии выбора в 0x33 вывод работает только на вход |
| 0x33.0-.3 | 0 | источник OE: периферийная линия e0 / e3 / e4 / e5 (one-hot) |
| 0x3F | 1 | инверсия выхода (неподключенная линия данных читается как 1) |
| 0x36 | 0 | крутизна фронта: 1 - быстрый, 0 - медленный |
| 0x39 | 0 | данные на выход: 1 - напрямую, 0 - с регистра IOE |
| 0x3B | 0 | в строку / столбец: 1 - напрямую с вывода, 0 - с регистра IOE |
| 0x3A | 0 | вход D регистра IOE: 1 - из строки / столбца (выходной регистр), 0 - с вывода (входной регистр) |
| 0x3D.0/.1 | 0 | такт регистра IOE: e1 / e4 |
| 0x3E.0/.1 | 0 | сброс регистра IOE: e2 / e5 |
| 0x3C | 1 | 0 только у выводов, которые не работают на выход |

Типовые комбинации (порядок секций: 33/34/36/39/3A/3B/3C/3D/3E/3F; s - крутизна фронта, oe - one-hot выбор OE):

| использование | биты |
|---|---|
| вход | `0 0 1 1 1 1 0 0 0 1` |
| выход | `0 1 s 1 0 1 1 0 0 0` (3F=1 - инвертированный выход) |
| TRI / двунаправленный | `oe 0 s 1 0 1 1 0 0 0` |
| не используется | `0 1 0 0 0 0 1 0 0 1` |

**Периферийная шина (OE, такт и сброс IOE):**
- 6 линий: e0 = POE0, e1 = PCLK0, e2 = PCLR0 (из ряда A); e3 = POE1, e4 = PCLK1, e5 = PCLR1 (из ряда B).
- Назначение линий: OE - e0, e3, e4 или e5; такт - e1 или e4; сброс - e2 или e5.
- Биты строки e секций 0x50 и 0xA6: линии e0 и e3 используют только бит .0, линии e2 и e5 - только бит .1, линии e1 и e4 - оба бита, которые всегда устанавливаются вместе.
- Источник линии: `0x50#i[e]` - трасса GH i (e0-e2) или GH 168+i (e3-e5); `0xA6#d[e]` - выделенный вход d.
- Инверсия линий: 0x43 (e0/e3), 0x44 (e1/e4), 0x45 (e2/e5); строка r = 0 относится к ряду A, r = 1 - к ряду B.
- На шину выводится только LC1 каждого LAB через свою трассу GH либо GV через 0x47. LC2-LC8 к шине не подключаются.
- Номер GH i, собственной трассы LC1 LAB столбца c (c -> i): 1->4, 2->16, 3->5, 4->19, 5->12, 6->10, 7->18, 8->13, 9->9, 10->1, 11->7, 12->20, 13->11, 14->2, 15->14, 16->17, 17->8, 18->15, 19->0, 20->3, 21->6.

**Выделенные входы как глобальные сигналы:**
- такт или сброс LAB: один бит в 0x41#k / 0x42#k;
- OE, такт или сброс IOE: `0xA6#d[e]` и бит выбора линии в IOE;
- данные: FINPGH -> PIA через переключатели `.maf`.

### 6.6 Режимы ячейки и управление LAB

**Управление LAB:**
- В каждом LAB 2 такт-линии и 2 сброс-линии. Ячейка выбирает линии битами 0x28 / 0x29.
- Источник линии k: выделенный вход (0x41#k / 0x42#k, бит d = FINP d: .0 = вывод 12, .1 = 73, .2 = 31, .3 = 54) или линия PIA / обратная связь (0x49#k / 0x4A#k, код как у 0x48).
- 0x2F.k - инверсия такт-линии k (тактирование по спаду); 0x30.k - инверсия сброс-линии k.
- Сброс внутри LAB активен единицей, неподключенная линия читается как 1. Поэтому у LAB с триггерами на неиспользуемых сброс-линиях установлен бит 0x30.k. Сброс с активным нулем (clrn) также дает 0x30.k = 1.

**Вычисление ячейки.** Неподключенный вход читается как 1. cin - перенос от LE k-1; перенос проходит через границу LAB: LC8 -> LC1 следующего LAB того же ряда.

```
обычный  (2D=1):      out  = LUT[in3*8+in2*4+in1*2+in0];  при 2E: out &= выход LE k-1 (каскад)
арифм.   (2D=0,2A=0): cout = LUT[cin*4+in1*2+in0];        out = LUT[in3*8+!cin*4+in1*2+in0]
счетчик  (2D=0,2A=1): cout = LUT[cin*4+in1*2+!Q];         sum = LUT[8+!cin*4+in0*2+!Q]
                      D = in3 ? sum : in2   (in3 = /LOAD);   при 2C: D &= in1 (синхронный сброс)
триггер  (06=1):      выход = Q;  CLR/PRE: в режиме 2B - CLR = line0 | (line1 & !in2), PRE = line1 & in2
```

- В режиме 2B in2 - данные асинхронной загрузки, а не вход LUT. При неподключенном in2 линия 1 работает как установка.
- Отдельного режима "только установка" нет. Предустановка (prn) реализуется как сброс инвертированного триггера.
- Триггеры TFF, JKFF, SRFF и DFFE реализуются как DFF и LUT с обратной связью от Q; LATCH - как комбинационная петля.
- Регистр IOE один на вывод и используется как входной либо как выходной. Предустановки и разрешения такта у регистра IOE нет.

### 6.7 Ресурсы, используемые схемами GMX

- Выводы: входы, выходы с медленным фронтом, инвертированные выходы и TRI. Регистры IOE не используются. OE шины данных DB0-7 подается через периферийную шину. Биты 0x43-0x45 равны 0.
- Такт и сброс LAB подаются только через 0x49 / 0x4A; 0x41 / 0x42 не используются.
- Все занятые ячейки работают в обычном режиме (2D=1), без переноса, каскада и счетчиков. 16 ячеек работают в режиме 2B.

## 7. Не определено

1. Работа режима 0x2B при 0x29 = 1.
2. Работа каскада (0x2E) через границу LAB.
3. Назначение бита 0x3C. Значение 0 встречается только у выводов, которые не работают на выход.
4. Полное назначение бита 0x3A.
5. Уровень на неиспользуемых выводах.
6. Раздельное назначение двух бит линий e1 / e4 периферийной шины. Оба бита рассматриваются как один переключатель.
7. Работа 0x2C без 0x2A и режима счетчика совместно с 0x2E.
8. Специальные источники данных выводов DATA0 и SDOUT.
9. Флаги `packed` (0xC0) и две дополнительные записи `.maf`.
