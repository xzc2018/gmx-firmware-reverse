# CPLD GMX (EPM7064SLC44, DD13): формат POF и схема

Исходные файлы схемы: [../cpld/](../cpld/).

| файл | содержимое |
|---|---|
| `gmx_cpld.tdf` | схема на AHDL |
| `gmx_cpld.acf` | кристалл, назначение выводов и макроячеек, параметры компиляции |
| `gmx_cpld.edo` | нетлист EDIF |
| `gmx_cpld_original.pof` | исходная конфигурация CPLD |
| `gmx_cpld_rebuilt.pof` | конфигурация, полученная компиляцией `gmx_cpld.tdf` |

Назначение выводов: [cpld_pins.csv](cpld_pins.csv).

## 1. Формат POF EPM7064S

### 1.1 База данных кристалла

Описание кристалла в MAX+PLUS II 10.23:
- `s7064044.daf` (MAX 7000S, 30609 бит);
- граф трассировки `m7064s.maf` (MCELL 64, GH 132, PIA 144, HIO 68, POE 6).

Файл `a7064044.daf` относится к MAX 7000AE (30746 бит) и для EPM7064S не применяется.

Выделенные входы:

| HIO | вывод | функция |
|---|---|---|
| 64 | 43 | GCLK1 |
| 65 | 44 | OE1 |
| 66 | 1 | GCLRn |
| 67 | 2 | OE2/GCLK2 |

### 1.2 Битовый массив

- Пакет 17 POF: заголовок `u32 0, u16 0, u32 30609, u16 1`, затем 3827 байт данных.
- Бит с адресом A: `byte[A >> 3] >> (A & 7) & 1`. Адрес A совпадает с адресом в DAF/MAF и с номером фьюза JEDEC.
- Пакет 5 содержит бит защиты, пакет 8 - CRC.

### 1.3 Карта фьюзов

| адреса | ресурс | кодирование |
|---|---|---|
| 0-28159 | матрица И | `A = L*7040 + (5k+p)*88 + w`: LAB L = 0..3, ячейка k = 0..15 в LAB, терм p = 0..4. 0 = литерал подключён. Все биты терма 1 - терм не используется (TRUE), все 0 - FALSE |
| | w = 0..71 | `w = 2j` - линия PIA j, `w = 2j+1` - её инверсия |
| | w = 72..87 | `w = 72+k` - разделяемый экспандер ячейки k той же LAB, равен `!PT0(k)` |
| 28160-28991 | конфигурация макроячеек | `28160 + 13*m + i`, см. 1.4 |
| 28992-30143 | PIA | 144 линии по 8 бит (`28992 + 8*line + s`), код "один ноль": 0 выбирает источник GH по ключу MAF |
| 30144-30197 | 6 глобальных OE | на линию 8 бит выбора источника (код "один ноль") и бит полярности `30152 + 9n` (0 - прямая, 1 - инверсия) |
| 30198-30581 | ячейки ввода-вывода | `30198 + 6k + i`, см. 1.5 |
| 30582-30584 | глобальные такты | см. 1.6 |
| 30585-30591 | не определено | во всех файлах 1 |
| 30592 | JTAG | 1 - включён |
| 30593-30608 | код пользователя | 16 бит, младший бит первым |

Неиспользуемые линии PIA компилятор заполняет источником по умолчанию; линия используется, только если на неё ссылается терм.

### 1.4 Биты макроячейки (i = 0..12)

| i | назначение |
|---|---|
| 0 | PT0: 0 - в OR. PT0 всегда подаётся на разделяемый экспандер |
| 1 | PT1: 0 - в OR, 1 - второй вход XOR |
| 2 | PT2: 0 - в OR, 1 - асинхронный сброс (активный уровень 1) |
| 3 | PT3: 0 - в OR, 1 - такт (при b5 = 1) или разрешение такта (при b5 = 0) |
| 4 | PT4: 0 - в OR, 1 - асинхронная установка (активный уровень 1) |
| 5 | 1 - такт от терма PT3, 0 - глобальный такт |
| 6 | 1 - сброс также от вывода 1 (GCLRn) |
| 7 | 1 - выход OR передаётся в OR следующей ячейки (параллельный экспандер k -> k+1); собственный XOR получает 0 |
| 8 | 1 - T-триггер |
| 9 | константа второго входа XOR при b1 = 0: 1 - VCC, 0 - GND |
| 10 | 1 - комбинационный выход (триггер обходится) |
| 11 | 1 - turbo выключен |
| 12 | глобальный такт: 1 - G1, 0 - G2 |

Функция ячейки:

```
D/T = (b7 ? 0 : OR(PTp, для которых bp = 0) | вход_цепочки) xor (b1 ? PT1 : b9)
вход_цепочки = выход OR ячейки k-1, если у неё b7 = 1
```

Разрешение такта действует при b3 = 1 и b5 = 0. Неиспользуемая ячейка: `1111010000001`.

### 1.5 Ячейка ввода-вывода

| i | назначение |
|---|---|
| 0-2 | источник OE, `v = i0 + 2*i1 + 4*i2`: 0..3 - POE2..POE5, 4 - GND (вход), 5 - POE0, 6 - POE1, 7 - VCC (постоянный выход) |
| 3 | крутизна фронта: 0 - быстрая, 1 - медленная |
| 4 | не определено (во всех файлах 1) |
| 5 | 0 - открытый сток |

### 1.6 Глобальные такты

`v = b30582 + 2*b30583 + 4*b30584`:

| v | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| G1 | !43 | !43 | !2 | 43 | 43 | 43 |
| G2 | 2 | !2 | 2 | 2 | !2 | !43 |

Значения 0 и 7 не определены. В GMX используется v = 6.

## 2. Схема CPLD GMX

### 2.1 Общие сведения

- Используется 40 макроячеек.
- JTAG выключен: выводы 7, 13, 32, 38 (TDI, TMS, TCK, TDO) работают как A0, A10, D6, D1. Программирование выполняется программатором.
- Регистры портов тактируются фронтом WR/ (вывод 43, G1), то есть концом цикла записи. Цикл записи в порт: IORQ/ = 0 при M1/ = 1.
- Регистры портов реализованы T-триггерами с `T = ena & (D xor Q)`, что эквивалентно DFFE. Компилятор строит такую же реализацию из `DFFE` в исходном тексте.
- Вывод 1 (RST_DLY) используется как обычный вход через PIA, глобальный сброс не используется.

### 2.2 Порт xx00

Дешифрация: A0 = A1 = A5 = 0.

| бит | регистр | сброс при RESET | назначение |
|---|---|---|---|
| D0-D2 | `conf[2..0]` | нет | CONF0..2, номер схемы FLEX |
| D3 | `nconf_r` -> NCONF | установка в 1 | RECONF: nCONFIG = !D3 |
| D3 | `reconf` | нет; сбрасывается чтением `#7AFD` | копия для чтения |
| D4 | `fixrom` | нет | FIXROM |
| D5 | `blkext` | да, если FIXROM = 0 | BLKEXT |
| D6 | `blkex2` | да, если FIXROM = 0 | BLKEX2 |
| D5, D6 | `blkext_rb`, `blkex2_rb` | нет | копии для чтения |

- Запись D3 = 1 устанавливает nCONFIG = 0 и останавливает FLEX. nCONFIG возвращается в 1 при RESET или при записи D3 = 0; после этого FLEX загружает схему с номером CONF.
- FIXROM = 1:
  - запрещает запись A16..A18 в `#7EFD`;
  - отменяет сброс A16..A18, BLKEXT и BLKEX2 при RESET;
  - отменяет загрузку регистра чтения (2.6).

### 2.3 Порт #7EFD

Дешифрация: A15 = 0, A14 = A10 = A9 = 1, A8 = 0, A5 = 1, A1 = 0, A0 = 1, при BLKEXT = BLKEX2 = 0. Все биты сбрасываются при RESET; A16..A18 - только при FIXROM = 0.

| бит | регистр | выход |
|---|---|---|
| D0 | `ewr` | EWR. Строб записи Flash: `WEFL = !(EWR & !MREQ/ & !WR/ & !A15 & !A14)`, окно 0000-3FFF |
| D1 | `vpp` | EVPP, напряжение +12 В на Flash |
| D2 | `mgen` | MagEnable: 1 - кнопка Magic заблокирована, BLKPK1 не действует |
| D4-D6 | `bank[2..0]` | RA16..RA18, банк 64 КБ Flash; запись только при FIXROM = 0 |

### 2.4 Копии битов ПЗУ Scorpion

- `#1FFD` (A15 = A14 = 0, A8 = 1, A5 = 1, A1 = 0, A0 = 1; при BLKEX2 = 0): `blk1` (D0, BLK1), `rom2` (D1, ROM2), `trdos` (D2, TRDOS).
- `#7FFD` (A15 = 0, A5 = 1, A1 = 0, A0 = 1 и одно из условий: `A14 & A8`, `A14 & BLKEXT`, `BLKEX2`): `rom1` (D4, ROM1), `blkpk1` (D5, BLKPK1). Запись разрешена при BLKPK1 = 0 или MagEnable = 1.

Все биты сбрасываются при RESET.

### 2.5 Теневой режим

| регистр | такт | функция |
|---|---|---|
| `trap_n` | спад MREQ/ | 0 при выборке команды из 3D00-3DFF, если ROM1 = 1 и (BLK1 = 0 или mg_idle = 0). Значение 0 асинхронно устанавливает `shadow` |
| `mg_n` | выборка команды из ОЗУ | значение вывода MG при MagEnable = 0; устанавливается в 1 любым чтением из ПЗУ |
| `shadow` | выборка команды из ОЗУ | `!mg_n`: 1 при нажатой Magic, иначе 0. Сбрасывается при RESET |
| `mg_idle` | спад `mg_n` | сбрасывается в 0 при приёме Magic. Устанавливается при RESET и при любом обращении к порту с A0 = A1 = A5 = 1 вне теневого режима |

Выборкой из ОЗУ считается выборка команды вне 0000-3FFF, а также в 0000-3FFF при BLK1 = 1 и mg_idle = 1. Чтением из ПЗУ считается чтение из 0000-3FFF при невыполнении условия `BLK1 & mg_idle`.

### 2.6 Последовательное чтение порта xx00

При RESET и FIXROM = 0 регистр `rb[7..0]` асинхронно загружается:

| rb0..rb2 | rb3 | rb4 | rb5 | rb6 | rb7 |
|---|---|---|---|---|---|
| CONF0..2 | RECONF | 0 | BLKEXT | BLKEX2 | `warm` |

- `warm` устанавливается первым чтением `#7AFD` и сбрасывается только при включении питания.
- При чтении `#78FD` (BLKEXT = BLKEX2 = 0) EO = rb0: при rb0 = 1 буфер DD11 закрыт.
- По окончании каждого чтения `#78FD` регистр сдвигается: `rb[] = (0, rb[7..1])`.

### 2.7 Буфер данных DD11

- `DIR = CONFD & WR/`.
- `EO = CONFD & !(IORQ/ = 0 & M1/ = 1) | (чтение #78FD & rb0)`. EO = 0 открывает буфер: в циклах ввода-вывода, а также всё время при CONF_DONE = 0.

### 2.8 Адрес Flash: CS27, CS1, A13

Flash 28F400 работает в байтовом режиме.

| бит адреса Flash | 0..13 | 14 | 15 | 16..18 |
|---|---|---|---|---|
| источник | A0..A13 Z80 | CS27 | CS1 | RA16..RA18 |

CS27 и CS1 являются адресными битами. CE# Flash постоянно активен, OE# = CSROM = RDR/ & CONF_DONE (диоды VD1, VD2): Flash выдаёт данные при чтении ПЗУ (сигнал RDR/ от FLEX) и во время загрузки FLEX.

Логическая страница ПЗУ `page` (16 КБ в банке) при CONF_DONE = 1:

| условие | page | содержимое (банк 4 / банк 1) |
|---|---|---|
| TRDOS = 1 | 3 | TR-DOS |
| ROM2 = 1 | 2 | теневой монитор |
| теневой режим, ROM1 = 1 | 3 | TR-DOS |
| теневой режим, ROM1 = 0 | 2 | теневой монитор / TR-DOS |
| иначе | ROM1 | 0 - ZX128, 1 - ZX48 |

На выводы выдаётся `CS27 = page0`, `CS1 = page1 xor page0`. Логический номер страницы соответствует порядку страниц в образе `gmx.rom`; в микросхеме страницы 1 и 3 каждого банка переставлены (физическая карта Flash: [GMX_findings.md](GMX_findings.md), раздел 1).

При CONF_DONE = 0 CPLD формирует адрес блока схемы FLEX в банке 0 (RA16..RA18 = 0 после RESET). Вывод A13 работает как выход (OE = !CONF_DONE, глобальный OE0), так как вывод ADD13 FLEX используется как WRBUF.

| CONF | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| адрес в образе | 0x2000 | 0x2000 | 0xC000 | 0x2000 | 0x8000 | 0xA000 | 0x4000 | 0x6000 |
| схема | Start Sch | Start Sch | Work Sch | - | PentaGON | Komposit | DK_test | Scheme 7 |

После включения питания CONF = 0, загружается схема по адресу 0x2000.
